# 2AIO Dashboard — 調査 → 計画 → 実装 → テスト → Push

1つの目的を、5つのフェーズに分けて通すためのローカルコンソール。
フェーズごとに **担当する SDK** と **使える権限** が変わり、フェーズ間は必ず人間の承認ゲートを通る。

```
..\start-dashboard.bat # Windows: ダブルクリックで起動（ブラウザも開く）
node server.mjs          # http://127.0.0.1:7801
npm test                 # フェーズ権限のテスト
```

## フェーズ

| # | フェーズ | 担当 | 権限 | 成果物 |
|---|---|---|---|---|
| 1 | 調査 | Claude | `Read Grep Glob TodoWrite · bash:readonly · write:artifact` | `01-investigate.md` |
| 2 | 計画 | Claude | 同上 | `02-plan.md` |
| 3 | 実装 | **Codex** | sandbox `workspace-write` | `03-implement.md` |
| 4 | テスト | Claude | `… · bash:readonly+test · write:artifact` | `04-test.md` |
| 5 | Push | Claude | `… · bash:readonly+git · write:artifact` | `05-push.md` |

司令塔（Claude）が調べ・計画し、実装だけを Codex に委譲する。
`write:artifact` は「`.2aio/runs/<id>/` の中しか書けない」という意味で、
**調査・計画・テスト・Push の各フェーズはリポジトリのコードを1行も変更できない。**

引き継ぎは会話ではなく成果物ファイル。計画フェーズは調査の `.md` を読んで始まり、
Codex はこの会話を一切見ずに `02-plan.md` だけを受け取る。

## 承認の扱い

- **フェーズは自動で進まない。** 各段の終わりで止まり、人間がゲートバーで進める / やり直す / 差し戻す。
- **承認の正本は `state.json` のフィールドだけ。** フェーズ起動時に毎回ディスクから読み直し、
  前フェーズの `gates[...]` が無ければ起動を拒否する。会話中の「承認します」は一切信用しない。
- **`git push` はエージェントからは実行できない。** どのフェーズでも承認カードすら出さずに拒否される。
  push はダッシュボードのボタンを人間が押した時だけ、サーバが実行する（2段確認・実行コマンドを表示）。
- 権限の範囲外のツールは承認カードになり、**人間が答えるまで SDK 側が本当に停止する**（タイムアウト無し）。

## 強制力の限界（正直な話）

この層が何を保証し、何を保証しないか。

| 部品 | 実効性 |
|---|---|
| `HARD_DENY`（push / `rm -rf` / `.env` / `sudo` 等） | ✅ **本当にブロックする。** 承認カードにも出さないので、人間が押しても通らない |
| フェーズ別の Bash 許可リスト | ✅ ブロックする。連結・パイプは**全区間**を検査し、リダイレクト（`>`）は書き込み扱いで承認送り |
| 書き込み先の限定（`write:artifact`） | ✅ ブロックする。`..` でディレクトリを抜ける経路も塞いである |
| 承認ゲート（`state.json`） | ✅ ブロックする。記録が無ければフェーズは起動しない |
| Codex の実装フェーズ | ⚠️ **`canUseTool` は Claude 側だけの機構。** Codex は自前の sandbox（`workspace-write`）に従う。上の許可リストは適用されない |
| フェーズの役割（「テスト担当は直さない」等） | ⚠️ **プロンプトによる宣言。** 書き込み権限で裏打ちされている範囲は強制、判断の範囲は指示のみ |

`settingSources: []` を指定して `~/.claude/settings.json` などの許可ルールを一切読み込まない。
これを外すと、環境ごとの設定でフェーズ権限が勝手に広がり、`canUseTool` を通らないツール呼び出しが発生する。

そして 2AIO 本体と同じ但し書きが、ここにもそのまま当てはまる —
**敵対的に振る舞う LLM に対する本当の境界はホスト OS だけであり、プロセス内の判定は境界ではなくヒューリスティックである。**

## 構成

| ファイル | 役割 |
|---|---|
| `phases.mjs` | フェーズ定義。**どこで何が許されるかの単一の正本。** 画面に出る権限表記もここから作られる |
| `lanes.mjs` | Claude / Codex の駆動。承認ゲートの発火点 |
| `server.mjs` | ラン状態（`.2aio/runs/<id>/`）・SSE・ゲート・push |
| `public/` | 画面。ビルド工程なし |
| `phases.test.mjs` | 権限のテスト。通ってほしくないものを厚く書いてある |
| `../start-dashboard.bat` | Windows 用ランチャ。依存確認 → 起動 → ブラウザを開く。ビルド工程は増やさない |
